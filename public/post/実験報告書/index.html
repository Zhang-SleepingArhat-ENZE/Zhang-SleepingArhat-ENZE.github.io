実験報告書(HTTP通信とDNS)

実験の概要

本実験の目的は、OSI参照モデルにおけるアプリケーション層を対象とし、実験により、DNS (Domain Name System)による名前解決の仕組みと、アプリケーション層の代表的な通信 プロトコルの一つであるHTTP(HyperText Transfer Protocol) の仕組みを理解することを目的とする。

  • DNSによる名前解決の観測：常用語法(dns,$resolvectl flush-caches,$nslookup www.anl.is.ritsumei.ac.jp)
  • HTTP GETの観測：常用語法(http)
  • HTTP GETを繰り返した時の挙動の観測：Web ページに対するHTTP GET の観測;UNIX コマンドによりHTTP GET を繰り返した時の通信の観測;

実験の手順と結果

Ex1:DNSによる名前解決の観測

手順
Core 内のWeb ブラウザでhttp://www.anl.is.ritsumei.ac.jp/exp/index.html を開いた 時の、DNS による名前解決をWireshark により観測

  • Q1:　Wireshark によりDNSクエリの通信が観測できていることを示す。DNSクエリの送信元ホスト(手元の計算機、つまり、Lubuntu が稼動している仮想計算機)と宛先ホスト(DNSサーバ)のIPアドレスはそれぞれ何か?この実験に限らず、送信元ホストと宛先ホストを混同しないように注意すること。またIPv4とIPv6で、参照すべきレコードがAとAAAAと異なるが、立命館大 ではIPv4のみがサポートされている点に注意して、どちらを参照すべきかを判断すること。ただしDNS応答に参照したいIPアドレスが含まれていない場合は、ターミナルで以下のコマンドを実行してから再度Wiresharkで通信を観測すること。

  • Ｑ1の結果:

  • Q2: DNS クエリは、どのような(L4とL3の)通信プロトコルにより転送されているか?

  • Q2の結果: DNSクエリは、通常はL3にIPv4/IPv6、L4にUDPポート53を使用し、レスポンスが512バイトを超える場合やゾーン転送などではTCPポート53が使われる。

  • Q3: pingコマンドをターミナル上で実行し、ホストwww.anl.is.ritsumei.ac.jp のIPアドレスが何か確認せよ．そしてWireshark でキャプチャしたDNS クエリに対する応答の画面を貼り、本IPアドレスが回答として含まれていることを示せ。やはりDNS 応答に本IPアドレスが含まれていない場合は、ターミナルでflush-cachesのコマンドを実行してから再度Wiresharkで通信を観測すること。

  • Q3の結果:

    • ホストwww.anl.is.ritsumei.ac.jp のIPアドレス: 133.167.45.8
    • Wireshark でキャプチャしたDNS クエリに対する応答の画面:

    • IP address: Q4: HTTP 通信の過程においてDNS による名前解決を観測するのではなく、nslookup により、ホスト名からDNSサーバにIPアドレスを直接問い合わせてみよ。具体的 には、ターミナル上で以下のようなコマンドを実行すればよい。 $ nslookup www.anl.is.ritsumei.ac.jp nslookupのキャプチャ画面を貼り、nslookup により得られたIPアドレスが、Wire shark で観測したDNS クエリに対する応答に含まれるIPアドレスと一致している ことを確認せよ。nslookup の実行結果では、2 種類のアドレスが表示されるが、そ れぞれのIP アドレスが表す意味は自身で調べた上で回答すること。なお、回答さ れるDNSサーバのIPアドレスについては、Wiresharkの結果と異なる場合がある が、気にしなくてよい
