実験報告書 – ネットワーク層プロトコル

実験の概要

本実験では、ネットワークエミュレータcoreを用いて仮想的なIPネットワークを構築し、Wiresharkでパケットをキャプチャ・解析することで、IP（Internet Protocol）およびICMP（Internet Control Message Protocol）の動作を理解することを目的とする。

実験の手順と結果

実験Ex1: ping コマンドによるパケットの観測

ネットワーク構成: 図4.6（2ホスト、5ルータのネットワーク）をcoreで作成。

Q2. n1 で n7 への ping コマンドを実行し、n7 からの応答があるか確認せよ。ping で用いられている通信プロトコルはなにか？

答え: ICMP（Internet Control Message Protocol）

Q3. echo request と echo reply のタイプ（番号）はいくつか？

答え: 応答があります。　echo request は 8、echo reply は 0

実験Ex2: 単一パケットの観察

n1 から n7 にむけて traceroute コマンドを実行する。キャプチャしたパケット群において、n1 から n7 に送信された最初のプローブパケットを見つけ出し、次の問いに答えよ。

Q1. IP パケットのヘッダにおける、上位プロトコルのフィールドの値を答えよ。また、その値に対応するプロトコル名も答えよ。

答え: 上位プロトコルフィールドの値は 17。対応するプロトコルは UDP。

Q2. IP パケットのヘッダの長さを答えよ。

答え: 20バイト （ヘッダ長フィールドの値は 5 × 4オクテット = 20バイト）

実験Ex3: 同じ用途の複数のパケットの観察 (traceroute プローブパケット)

キャプチャしたパケット群において、traceroute によって n1 から n7 に対して送信された一連のプローブパケットについて、次の問に答えよ。

Q1. 変化している IP パケットヘッダフィールドはなにか？

答え: TTL（Time To Live） と Dst Port が変化する。TTLは1ずつ増加し、Dst Portはプローブごとにインクリメントされる。

TTL:1->2->3->4 Dst Port:33434->33439->33442

実験Ex4: 同じ用途の複数のパケットの観察 (traceroute 応答パケット)

n1 から一番近い IP ルータから送信された ICMP time exceeded メッセージ群に着目せよ。

Q1. IP パケットヘッダの identifier フィールドの値と、TTL フィールドの値はどのように変化しているか？

答え: identifier は同じ値（元のプローブパケットを識別するために固定）、TTL は応答パケットごとに異なる（通常はルータから送信される時点の値）。 Identifier 递增 TTL 固定

実験Ex6

図4.6に示すネットワークにおいて，経路に障害を発生させその時の様子を観測せよ． n1 でn7へのpingコマンドを実行し，使用されている経路を確認せよ．その後，使用さ れているn2-n6間の経路の任意のリンクのパケットロス率をpingコマンドを実行した状 態で100%にし，経路を切断し様子を確認する．例えば，「n1-n2-n3-n4-n6-n7」という経路 ができていることを確認した場合，n2-n3やn3-n4，n4-n6のいずれかのリンクのパケット ロス率を100%にすることで経路を切断する．

Q1. 経路に障害が発生した場合，echorequestパケットの流れはどのように変化するか？ 各ルータでパケットをキャプチャして観察し，障害発生前と後のパケットの流れを 確認せよ

障害発生前は，n1 から n7 への echo request パケットは，ルーティングテーブルに従って最短経路を通過していた． 図の例では，通常時の traceroute の結果より， n1 → n2 → n5 → n6 → n7 の経路が利用されていることが確認できる． 各ルータでパケットキャプチャを行うと，ICMP Echo Request パケットは n2，n5，n6 を順番に通過し，最終的に n7 に到達していた． その後，使用中であった経路上のリンク（例：n5-n6 間）のパケットロス率を 100% に設定すると，そのリンクを通過できなくなり，一時的に ping が途切れた． 障害発生直後は，n5 までは Echo Request パケットが到達するが，n6 側には転送されず，パケットが破棄される様子を確認できた． しかし，ルーティングプロトコルが障害を検知すると，別経路への再計算が行われ，新たに n1 → n2 → n3 → n4 → n6 → n7の迂回経路が選択された．その結果，Echo Request パケットは n3，n4 を経由して再び n7 に到達するようになった．つまり，経路障害発生時には，

  • 障害リンクまでパケットが到達する
  • 障害箇所でパケットが破棄される
  • ルーティングテーブルが更新される
  • 別経路へ自動的に迂回して通信が再開される という流れになることを確認できた．また，障害発生後の traceroute 結果からも，経由ルータが n5 から n3・n4 に変化しており，通信経路が切り替わったことを確認できた．

Q2. 経路に障害が発生し宛先に届かないパケットがある場合，ルータはどのようなパケッ トを送信するか？

経路障害によってパケットが宛先へ到達できない場合，ルータは送信元に対して ICMP（Internet Control Message Protocol）のエラーパケットを送信する． 今回のキャプチャでは，

  • ICMP Destination unreachable
  • Code: 3 (Port unreachable) が確認できる． これは，「宛先に到達できない」ことを通知するための制御メッセージであり，ルータや宛先ホストが送信元へ返送する． したがって，経路障害発生時には，通常のデータパケットの代わりに ICMP のエラーメッセージ（Destination Unreachable など）が送信されることを確認できた．

Q3.

4.5.1 T1: IPパケットのペイロード長の算出方法

IPパケットのペイロード長は，「IPパケット全体の長さ」から「IPヘッダ長」を引くことで求めることができる．

計算式

[ \text{IPペイロード長} = \text{IPパケット全長} - \text{IPヘッダ長} ]

今回の実験で観察した traceroute のプローブパケットでは，Wireshark において IP ヘッダの Total Length フィールドと Header Length(IHL) フィールドを確認することができた．

例えば，

  • IPパケット全長 : 1500 byte
  • IPヘッダ長 : 20 byte

であった場合，IPパケットのペイロード長は，

[ 1500 - 20 = 1480 \text{ byte} ]

となる．

IPヘッダ長の求め方

IPヘッダ長は IHL（Internet Header Length）フィールドで表され，4オクテット単位で記録されている．

通常の IPv4 パケットでは，

  • IHL = 5

であるため，

[ 5 \times 4 = 20 \text{ byte} ]

となる．

考察

IPパケットのペイロード部分には，TCP，UDP，ICMP などの上位プロトコルのデータが格納される．
今回の traceroute 実験では，UDP パケットが IP パケットのペイロードとして含まれていることを確認した．

4.5.2 T2: 経路に障害が発生した場合の動作

経路に障害が発生した場合，ルータはリンク断やパケット転送失敗によって障害を検知する．
今回の実験では，通信経路上のリンクに対してパケットロス率を 100% に設定することで経路障害を発生させた．

障害発生前の経路

障害発生前は，echo request パケットは以下の経路で転送されていた．

[ n1 \rightarrow n2 \rightarrow n5 \rightarrow n6 \rightarrow n7 ]

各ルータでパケットキャプチャを行うと，ICMP Echo Request パケットが n2，n5，n6 を順番に通過していることを確認できた．

障害発生後の動作

例えば n5-n6 間のリンクを切断すると，パケットは n5 までは到達するが，その先へ転送できなくなる．
そのため，一時的に ping の応答が途切れることを確認した．

また，Wireshark において ICMP Destination Unreachable パケットを観測することができた．
これは，宛先へパケットを転送できないことを通知するための ICMP エラーパケットである．

経路変更後

障害を検知した後，ルータはルーティングテーブルを更新し，利用可能な別経路を再計算する．

その結果，通信経路は以下のように変更された．

[ n1 \rightarrow n2 \rightarrow n3 \rightarrow n4 \rightarrow n6 \rightarrow n7 ]

traceroute の結果からも，経由ルータが n5 から n3・n4 に変化したことを確認できた．

まとめ

経路障害発生時には，以下の流れで通信経路が変更されることを確認した．

  1. ルータがリンク障害や転送失敗を検知する
  2. 障害リンクへの転送を停止する
  3. ルーティングテーブルを更新する
  4. 利用可能な別経路を再計算する
  5. パケットを新しい経路へ迂回転送する

このことから，IPネットワークでは障害発生時に自動的に迂回経路へ切り替えることで，通信を継続できることが分かった．
